Code Block Toolbar

Problem

The prism plugin in for next does not offer the toolbox, it only supports the copy-tp-clipboard button. But for blogs with large content, they can be more readable with show/hide codes.

The problem is adding a button to show/hide code blocks in blogs. Note that code blocks will not only be used for codes. For example, in leetcode blogs, I use code blocks to display test cased and explanations.

Assumptions

  1. Real codes will have its programming language mentioned after the code block prompt. And the real codes can be displayed or hidden.
  2. For all other use cases, I will not mentioned the programming language and they cannot be hidden.

Solutions

  1. Register a drop down action registerCodeWithDropDown in NexT’s global JS handlers next/source/js/next-boot.js.

  2. Implement the action in next/source/js/utils.js. In NexT, all the code and code blocks are wrapped inside a <figure> element, with the programming language marked or plaintext for unmentioned code blocks.

  3. For all the elements that has the programming language marked, we wrap the codes in a <details>. This will create a drop down button and I name the button using the language and add to the <summary> element. All names will be transferred to upper case.

Support Emoji

Problem

The default renderer in Hexo is hexo-renderer-marked, which does not support adding emoji in markdown. The problem is finding a renderer to support emoji for Hexo.

Solutions

  1. Tried to find emoji-friendly plugin hexo-filter-github-emojis Not working. Tested with NexT theme, will affect the live2d-widget display, its special characters in js files will also be escaped. Thus it will throw bugs in the console and live2d-widget component can not be displayed.
  2. Find a new rendered for hexo markdown hexo-renderer-markdown-it-plus Is risky. Git repository is not well maintained, with many issues unresolved.
  3. Use the hexo-renderer-markdown-it, a faster and CommonMark compliant alternative for Hexo.
    • Install new renderer.
    • Add config for the new renderer.

Follow Up

Q: Why the switch is not displaying circular expanding animation as is it in other blogs’s demo?

A: To answer this question we need to know what each fields means in darkmode_js config. For backgroundColor, it will set the webpage background color, which will override the value set in NexT. Changing it will not affect the animation. For mixColor, it is a new color that will be overlaid on some of the components and it is the key to the animation.

If we set $content-bg-color-dark = white; and mixColor: '#333' and backgroundColor: 'transparent', we can see the animation. The animation will change the original dark mode style and is not elegant, thus I choose to opt out the animation and keep the config in NexT.
