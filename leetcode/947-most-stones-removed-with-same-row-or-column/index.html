947. Most Stones Removed with Same Row or Column

Posted on 2022-11-15 Edited on 2023-01-14 In Leetcode

Problems

On a 2D plane, we place n stones at some integer coordinate points. Each coordinate point may have at most one stone.

A stone can be removed if it shares either the same row or the same column as another stone that has not been removed.

Given an array stones of length n where stones[i] = [xi, yi] represents the location of the ith stone, return the largest possible number of stones that can be removed.

Examples

Constraints

Solutions

Overview

We are given n stones on a 2D plane with integer coordinates. We need to return the maximum number of stones that can be removed such that each stone we remove shares either the same row or column with any other stone that has not been removed.

In order to check if we can remove a stone, we would need to find if it shares a row or column with any other stone. This can be efficiently done if we can represent this structure in form of a Graph, such that there is an edge between stones that shares a row or column. This way, any stone with a non-zero degree can be removed because that means there exists at least one stone with the same row or column. So now we know the way to find if we can remove stones, we need to find what’s the best order of the stone removal to maximize the number of stones that can be removed.

The graph that we built could have a number of connected components. We need to process each component separately as they are independent of each other (A stone in one component doesn’t share a row or column with a stone in any other component). For one component it can be observed that we can remove all the stones except the last one. This can be easily proved using DFS, we can start DFS from any stone and keep removing the stones in the topological order except the one that we start the DFS with. Hence, in each component, we will be left with one stone and therefore the number of maximum stones we can remove will be total stones minus the number of connected components.

DFS

Algorithm

To build the graph, we will iterate over every pair of stones and add the edge between them if they have the same row or column in the adjacency list. We can then iterate over the stones and start DFS from it if it’s not been traversed yet. Each time we start the DFS, we will increment the count of components.

Complexity

NNN is the number of stones. EEE is the number of edges in the graph.
Time: O(N2+E)O(N^2+E)O(N2+E)
Building the graph costs O(N2)O(N^2)O(N2). DFS traverses costs O(N+E)O(N+E)O(N+E). This is because each stone is only visited once. In addition, when we iterate over the edge list of each stone, we look at each edge once.
Space: O(N+E)O(N+E)O(N+E)

DSU (Union Find)

Algorithm
  1. Initialize the representative of each stone as itself in the array rep and size as 1 in the array size.
  2. Initialize a variable stonesCount with the number of stones given.
  3. Traverse over every pair of stones and for each pair check if they share the row or column, if yes perform the union of the stones and update the counter variable stonesCount accordingly.
  4. Return length(stones) - stonesCount.
Complexity

NNN is the number of stones.
Time: O(N2∗log∗N)O(N^2*log^*N)O(N2∗log∗N), log∗Nlog^*Nlog∗N is the time complexity for Find or Union operation in DSU.
Space: O(N)O(N)O(N)

Optimization for DSU and DFS

Intuition

In the previous approaches, the building of the graph was a costly task: we had to iterate over every pair of stones to check if they share the row or column. Can we do better? Can we connect the stones in a different way without iterating over every pair? One thing to observe here is that we only care about the number of components not the structure of the graph. So as long as the number of components is the same, we can make it.

We know the stones with the same row are connected, so instead of checking for all the pairs, we can use the row to represent the stones with this row, similarly for the same column. For example, if we have a stone at (x, y), then we connect all the stones with the same x coordinate, and similarly we connect all the stones with the same y coordinate. Now we can connect all the stones under the x-coordinate with those under the y-coordinate. This is equivalent to connecting the x and y itself.

But we need a way to distinguish between the same value for x-coordinate and y-coordinate. For this, we add the value K=10001 to the y-coordinates to map them in different ranges. We chose the value 10001 as the range for the coordinates is [0, 10000].

Optimized DFS
Complexity

KKK is the number for x or y coordinates. NNN is the number of stones. EEE is the number of edges in the graph.
Time: O(E+K)O(E+K)O(E+K)
Building the graph costs O(N)O(N)O(N). DFS traverses costs O(E+K)O(E+K)O(E+K). The number of edges in the graph is O(E)O(E)O(E), the number of vertices in the graph is O(K)O(K)O(K). So the total time complexity is O(N+E+K)O(N+E+K)O(N+E+K). As we have N≤KN \leq KN≤K, time would be O(E+K)O(E+K)O(E+K).
Space: O(K)O(K)O(K)

Optimized DSU
Complexity

Time: NNN is the number of stones.
Time: O(N∗log∗K+K)O(N*log^*K+K)O(N∗log∗K+K)
log∗Klog^*Klog∗K is the time complexity for Find or Union operation in DSU. Initializing parent and size costs O(K)O(K)O(K).
Space: O(K)O(K)O(K)
